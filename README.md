# esp32s3-app2

ESP32-S3-DevKitC-1 兼容板（N16R8）+ ST7789 SPI 屏（240×320，横屏 320×240）。

**目标**：在这块板上跑 NES 模拟器（Super Mario Bros）。

硬件详情见 [`docs/hardware.md`](docs/hardware.md)。

- [x] ST7789 显示层：双缓冲 + 核 1 推屏任务 + 基本绘图 → `main/display.c`
- [x] 帧率实测：双缓冲 + 核 1 推屏任务

## 代码结构

| 文件 | 作用 |
|---|---|
| `main/main.c` | 启动流程：板级信息 → 初始化屏 → 启动模拟器 |
| `main/display.c` | ST7789 显示层。双缓冲 + 核 1 推屏任务，对上层只暴露「帧缓冲 + 推屏」 |
| `main/nes_emu.c` | 适配层。把 nofrendo 的 8 位调色板画面转成 RGB565 画进帧缓冲 |
| `main/roms/` | 内置 ROM（公有领域测试 ROM） |
| `components/nofrendo/` | NES 模拟器核心，取自 [retro-go](https://github.com/ducalex/retro-go)，**未改动源码** |
| `components/nofrendo/rg_system.h` | 唯一的粘合层：nofrendo 只需要日志 / CRC32 / IRAM_ATTR 三样东西 |

### 画面怎么放

NES 输出 256×240，裁掉上下各 8 行 overscan 得 256×224。屏幕横屏是 320×240，
**论面积 224 行放得下，但两块帧缓冲塞不进内部 RAM**，所以竖着抽行：
**每 7 行丢 1 行**，224 × 6/7 = 192。整数运算不用插值，几乎不花 CPU。
横向 256 不缩，像素保持 1:1 最锐利。

192 这个高度是被内存顶出来的，不是随便定的：能凑出大块的堆区在 `app_main` 时
只剩约 268 KB 连续，NES 的 vidbuf 先占 64 KB，两块帧缓冲各上限约 102 KB。
224 行（2×112 KB）和 208 行（2×104 KB）实测都是分配失败。
详细的账在 `main/display.h` 和 [`docs/hardware.md`](docs/hardware.md) §7。

帧缓冲**只覆盖这块 256×192 的画面区**，不是整屏（见 `display.h` 的 `DISP_FB_W/H`）。
黑边（左右各 32 列、上下各 24 行）由 `display_init()` 开机时清一次、之后再不碰。

⚠️ 帧缓冲**不能放 PSRAM**：`spi_master` 用 `esp_ptr_dma_capable()` 判断能否直接
DMA，那个函数只认内部 DRAM 地址段，PSRAM 指针一律返回 false，驱动会每条带临时
malloc 一块内部缓冲再 memcpy —— 每帧多拷一整屏，数据最后照样落在内部 RAM。

### 已知问题：轻微撕裂

这块屏没引出 TE 信号，推屏和面板扫描无法同步，画面剧烈变化时会看到撕裂。
详见 [`docs/hardware.md`](docs/hardware.md) §7。

### 已知问题：摇杆两轴不独立（未解决）

四个大按键工作正常，**摇杆的方向映射还没跑通**。现象：

- 推任何一个方向，X/Y 两路 ADC 读数**总是同向变化**，从不独立
- 按键标定实测：手推的「上」和「右」相差 90°，产生的电信号向量却只差 **11°**
  （53.6° vs 43.4°）—— 两个基向量几乎共线，任何线性变换都解不出正交坐标系
- 沿「左下↔右上」推：平滑、满量程 0~4095；沿「左上↔右下」推：抖动剧烈

量化：连续采样 100 帧、全程大幅推动摇杆，两路的**相关系数 r = +0.9990**，
同向分量 `(X+Y)/2` 跨度 4072（满量程），正交分量 `(X-Y)/2` 跨度只有 128（3%，噪声级别），
四象限只覆盖到 `++` 和 `--`。**输入端只有一个自由度。**

**已排除的**（每条都有实测）：

| 怀疑 | 怎么排除的 |
|---|---|
| 引脚配错 | 扫描 GPIO1~8 全部 ADC 通道，只有 1 和 2 有信号，跨度均 >4000 |
| 某一路悬空 | 「下毒」测试：先读恒 4095 的悬空脚充满 S/H 电容，再读目标通道。两路偏移均 ±13 以内，都被真实低阻源驱动 |
| 两路短路 | 扩展板 `X`↔`Y` 不通；GPIO1↔GPIO2 也不通 |
| 洞洞板锡桥 | 同上，万用表通断档验过 |
| GND / 供电 | 四个按键工作正常 |
| 摇杆机械损坏 | 手感正常，两个方向阻尼一致 |
| 装配角度偏 45° | **几何上不可能**：旋转是保角变换，推右和推上物理差 90°，任何装配角度下电信号也必须差 90°，不可能压缩成 11° |

**根因尚未定位。** 值得注意的是：`2a60a66`「真手柄接上了」那个提交时摇杆是能用的，
所以这是后来出现的故障，不是设计问题。

⚠️ 两条走过的弯路，记下来避免重蹈：

1. 曾用「连读两次间隔 1 ms，读数一致」排除悬空引脚 —— **这个推论不成立**。
   悬空脚阻抗极高，S/H 电容的电荷能维持远超 1 ms，两次读数当然一致。
   正确的判据是上面那个「下毒」测试。
2. 从第一份数据起「两轴不独立」的特征就一直在，却先后加了 45° 旋转、两点标定
   去拟合它。**这类问题应先把硬件排除干净，再动代码。**

排查工具：`main/input_gamepad.h` 顶部的 `PAD_DIAG_SCREEN` 改成 1，开机把摇杆
位置实时画到屏上（按大按键 A 退出）。画的就是 `poll()` 用的同一套坐标，
**点跟着手走 = 映射正确**；屏下方同时显示两路原始 ADC 读数，
只推一个方向时应该只有一个数字大幅变化。

### ⚠️ 克隆后先补 ROM

`main/roms/smb.nes` 是版权物，**不在仓库里**（见 `.gitignore`）。
新克隆的副本缺这个文件会**链接失败**（`main/CMakeLists.txt` 的 `EMBED_FILES` 引用了它）。

自备一份《超级马里奥兄弟》的 `.nes`，放成 `main/roms/smb.nes` 即可。
不想弄的话把 `main/nes_emu.c` 顶部的 `ROM_CHOICE` 改成 `1`/`2`/`3`，
并从 `EMBED_FILES` 里删掉 `roms/smb.nes` 那行 —— 剩下三个公有领域测试 ROM 随仓库分发。

### 换 ROM

把 `.nes` 文件放进 `main/roms/`，加到 `main/CMakeLists.txt` 的 `EMBED_FILES`，
再改 `main/nes_emu.c` 顶部的 `ROM_CHOICE` 和对应的 `asm("_binary_..._nes_start")` 符号名
（符号名由文件名生成：`foo-bar.nes` → `_binary_foo_bar_nes_start`）。

### 操作（手柄）

JoyStick Shield，接线见「接线」一节。两路输入**并存**（按位或），
串口键盘留着当调试后路 —— 手柄接错脚或者摇杆调不对时还能把游戏开起来对照。

| 手柄 | 作用 |
|---|---|
| 大按键 A | A（跳） |
| 大按键 B | B（跑 / 发射） |
| 大按键 C | SELECT |
| 大按键 D | START |
| 摇杆 | 上下左右 —— **目前不可用**，见「已知问题：摇杆两轴不独立」 |

上电时**手别碰摇杆**：开机要采 16 次静止读数做中位校准，碰着会被判定为
「没接好」而整路禁用（按键不受影响）。

### 操作（串口键盘）

真手柄到货前的临时方案，现在仍作为调试后路保留。
`idf.py monitor` 会把你敲的字符经串口发给板子。

```bash
idf.py -p /dev/cu.usbserial-A5069RR4 monitor
```

**焦点要在 monitor 窗口里**，然后：

| 键 | 作用 |
|---|---|
| `W` `A` `S` `D` 或方向键 | 上下左右 |
| `K` 或 `Z` | A（跳） |
| `J` 或 `X` | B（跑 / 发射） |
| 回车 | START |
| Tab | SELECT |
| 空格 | 全部松开（按键卡住时用） |
| `Ctrl+]` | 退出 monitor |

**限制**：串口只有「按下」没有「松开」事件，所以每次按键让按钮保持 250ms
（`input_serial.c` 的 `HOLD_MS`），长按靠终端的按键重复维持。因此：

- 长按开头有个停顿（终端的重复延迟），马里奥会先走一步再连续跑
- 点不出「轻跳」，每次跳跃都是固定时长

把系统的「按键重复速度」调到最快、「重复前延迟」调到最短会好很多。
接上真手柄后这些问题都不存在。

### 调色板

NES 的颜色本质是 NTSC 相位信号，没有唯一正确的 RGB 值，各家解码出来色相差别不小。
nofrendo 内置 6 套，改 `main/nes_emu.c` 顶部的 `NES_PALETTE` 即可切换，无性能影响。

当前用 `NES_PALETTE_NESCLASSIC`（任天堂 NES Classic Edition 的官方调色板）——
拿马里奥标题画面的 4 个关键色跟参考画面比对，它的总色差最小。
默认的 `SMOOTH` 在天空色 `$22` 上是 6 套里唯一 G>R 的，会让天空偏青蓝而不是紫蓝。

另外还有个 `NES_SATURATION`（百分比，100 = 原样，当前 150）。
这 6 套调色板的红色 `$16`（马里奥的帽子衣服）**都偏暗** —— R 分量只有常见
FCEUX 调色板 `(216,40,0)` 的 67%~74%，在小屏上看着发褐，换哪套都一样。
所以围绕亮度拉开饱和度：灰阶和白色不受影响，只有带颜色的像素变鲜艳。

| $16 | 饱和度 |
|---|---|
| (146, 52, 4) 发褐 | 100% |
| (182, 41, 0) | **150%（当前）** |
| (203, 35, 0) 接近 FCEUX 观感 | 180% |

只在开机建表时算一次，运行时零开销。

### 性能诊断

`main/nes_emu.c` 顶部把 `DIAG_TIMING` 改成 `1`，开机会先跑一遍分阶段计时，
把每帧耗时拆成 CPU 模拟 / PPU 渲染 / 调色板转换 / 推屏四段。换硬件或调优时很有用。

## 接线

### ST7789 屏

| 屏丝印 | 开发板 |
|---|---|
| GND | GND |
| VCC | 3V3 |
| SCL / SCK | GPIO12 |
| SDA / MOSI | GPIO11 |
| RES | GPIO13 |
| DC | GPIO14 |
| CS | GPIO10 |
| BLK | GPIO9（或直接 3V3 常亮） |

改引脚改 `main/display.h` 顶部的 `DISP_PIN_*`。SCK/MOSI/CS 这三个是 SPI2 的
IOMUX 原生脚，换成别的会降到 40 MHz，别动。

### JoyStick Shield V1.A（手柄）

Arduino UNO 的扩展板，**插不到 DevKitC 上**，只能飞线。走板子中央那个 6×2 的
黄色排针 —— 底边 Arduino 排母的丝印被排母本体挡住，数针位容易错一位。
黄排针旁边就印着针位表：

```
上排:  V  A  C  E  K  X
下排:  G  B  D  F  3  Y
```

| 黄排针 | 开发板 | 用途 |
|---|---|---|
| G | GND | |
| 3 | **3V3** | ⚠️ 不是 `V`，`V` 是 5V |
| X | GPIO1 | 摇杆 X（ADC1_CH0） |
| Y | GPIO2 | 摇杆 Y（ADC1_CH1） |
| A | GPIO15 | 大按键 A → NES A（跳） |
| B | GPIO16 | 大按键 B → NES B（跑） |
| C | GPIO17 | 大按键 C → SELECT |
| D | GPIO18 | 大按键 D → START |

`V`、`E`、`F`、`K` 空着（E/F 是两个小键，K 是摇杆按下，留给存档/复位）。

⚠️ **板子左边的 3V3/5V 拨动开关必须拨到 3V3**。摇杆是两个电位器跨在 VCC 和
GND 之间，拨 5V 档输出就是 5V，而 ESP32-S3 的 GPIO 不是 5V 耐受的。

摇杆两轴必须落在 GPIO1~10（ADC1 的范围），9~14 已被屏占用，实际只剩 1/2/6/7/8。
改引脚改 `main/input_gamepad.h` 顶部的 `PAD_PIN_*`。

**当前状态**：四个按键已验证正常；**摇杆方向映射尚未跑通**，
见上面的「已知问题：摇杆两轴不独立」。

**接线时断电**，插好再上电。

## 编译烧录

```bash
. ~/esp/esp-idf/export.sh          # 每个新终端都要执行一次
idf.py build
idf.py -p /dev/cu.usbserial-A5069RR4 flash monitor
```

烧录用丝印 `COM` 的 Type-C 口（板载 FTDI FT232R 桥）。本机上枚举为
`/dev/cu.usbserial-A5069RR4`（A5069RR4 是这颗 FT232R 的序列号，换板子会变，
用 `ls /dev/cu.usbserial-*` 确认）。退出串口监视器：`Ctrl+]`。

`COM` 口没枚举出设备就换另一个 Type-C 口（丝印 `USB`，原生 USB），
**按住 BOOT 再上电**进下载模式，端口名形如 `/dev/cu.usbmodem*`。

## 换屏 / 显示不正常

`main/display.c` 对上层只暴露「一块 RGB565 帧缓冲 + 推屏」，换屏只需改
`main/display.h` 顶部的宏，上层代码不动。调的时候**一次只改一个**再烧：

| 现象 | 改哪个 |
|---|---|
| 画面偏移 / 边缘花条 | `DISP_GAP_X` / `DISP_GAP_Y`（满屏 240×320 用 0；170 列的窄屏用 35） |
| 上下或左右颠倒 | `DISP_MIRROR_X` / `DISP_MIRROR_Y` |
| 颜色像底片 | `DISP_INVERT_COLOR` |
| 红蓝互换 | `DISP_BGR_ORDER` |
| 花屏 / 雪花 | `DISP_SPI_HZ` 降到 40 MHz 或更低 |
| 分辨率变了 | `DISP_W` / `DISP_H`，以及画布 `DISP_FB_W` / `DISP_FB_H` |

⚠️ 换屏时 `DISP_GAP_Y` 和 `DISP_H` 要一起改。只改一个的典型症状是：画面能正常显示，
但整体偏移、并且屏幕有一条边永远刷不到 —— 看着像「边缘被浪费了」。
